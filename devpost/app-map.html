How the demo fits together

Study Buddy is a local Streamlit study-chat interface. In its approved demo mode, it accepts text and shows an honest notice; it does not analyze the material or create AI-generated study content.

Reference route through the code

This route is a map for exploring the implementation; it has not yet been toured together.

  1. app.py — search for with st.form("study_input_form") to find where the learner enters and sends text.
  2. app.py — search for if not live_mode to see how demo mode is selected, then follow preview_notice().
  3. sample_responses.py — open preview_notice(); its wording explicitly says the text was not analyzed and no request was sent. Back in app.py, the reply is appended to session messages and shown in the chat.

To change this, start here

  • Change the visible title, topic suggestions, or study-action labels: app.py.
  • Change the no-analysis demo wording: sample_responses.py, function preview_notice().
  • Adjust the optional provider prompts or explain quota errors: ai_client.py.
  • Check that the app remains honest in demo mode: test_app.py, tests beginning test_configured_key_ and test_demo_mode_.

A practice to reuse

The requirement says demo mode must not imply that pasted material was analyzed. test_app.py checks the visible notice even when a key is configured, while sample_responses.py supplies that exact honest message. On another project, turn an important boundary into an observable check so a later change cannot quietly promise more than the app does.

Run it again

From the project folder, run python -m streamlit run app.py, then open the local address Streamlit prints (usually http://localhost:8501). Live AI stays off unless deliberately enabled and may require paid quota.
